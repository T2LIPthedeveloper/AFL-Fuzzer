Decision question: Should we onboard Greptile onto our codebases?

Short answer: Yes, as a supplement to human review on multi-service and multi-file Spring work. Greptile is not a full replace for humans. Greptile overlaps Copilot on many critical defects. Greptile still adds unattended GitHub packaging, confidence scores, and cross-file edge finds that help merge decisions.

Copilot in this report means Cursor Bugbot. GitHub Copilot did not run (credits / access). This report skips a “no review” baseline.

3. Baseline service on main-spring

main-spring adds a working Spring Boot fuzzer service.

REST endpoints start campaigns, read status, and mutate seeds.

Internal packages act as microservice boundaries inside one deployable unit:

  • api — REST controllers
  • campaign — campaign loop and seed queue
  • mutation — mutation engine
  • targetclient — HTTP target client
  • model / config — DTOs and settings

Default port is 8088.

Greptile blocked on mutation bound risk, unsafe shared strategy-map updates, and a splice no-op path.

Copilot did not need a separate small-tier pass for the onboarding decision. The small tier is mostly feature polish.

A careful human can approve after bound and concurrency checks. A rushed human may miss the shared-map risk.

Greptile understood HTTP and device scheduling.

Greptile found disconnected feedback paths.

Greptile found schedule identity collision across endpoints.

Greptile found silent dictionary loss in packaged JARs.

A careful human likely finds the missing record call. A human may miss JAR dictionary load and unbounded rounds.

9. Graph / AST value

Many defects need multi-hop reasoning.

Examples: a service method exists, but the campaign loop never calls it.

Examples: one class writes stats under one key, another class reads energy under a different key.

Examples: response locals exist, but coverage receives nulls.

Greptile’s graph story matches these defect types.

Copilot also found most of them without Greptile’s hosted index.

Conclusion: Graph-style reasoning matters. Greptile is not the only system that can do it. Greptile forces that reasoning on every PR without a manual Cursor run.

13. Onboarding decision

Recommend onboard Greptile: Yes, with conditions.

  1. Keep human approval required on protected branches.
  2. Use Greptile for unattended first-pass review on Spring and multi-file services.
  3. Enable TREX on at least one service class of PR if you pay for Greptile. Static review alone leaves runtime gaps.
  4. Keep Copilot/Cursor review where engineers already work in Cursor.
  5. Do not treat Greptile confidence scores as a sole merge gate.

Best posture: Human + Greptile (or Human + Copilot). Two automated tools plus a human give the highest recall, but one automated tool is enough for most teams.

Weak posture: Greptile alone with no human. Packaging helps. Accountability still needs a person.
